어딧세이 관리자 기능 사용 가이드
처음 사용하는 팀원을 위한 메모장 안내서
작성 기준: 2026년 10월 2일

==================================================
1. 먼저 알아두세요
==================================================

관리자는 사이트에 올라온 내용을 관리하는 사람입니다.
현재 프로그램에서는 컴퓨터 환경마다 관리자 1명을 지정합니다.

관리할 수 있는 내용:
- 여행지
- 커뮤니티 게시글
- 리뷰
- 커뮤니티 댓글
- 여행톡
- 여행톡 댓글

할 수 있는 일:
- 내용 수정
- 게시 중단: 내용을 지우지 않고 일반 화면에서 숨기기
- 복원: 중단했던 내용을 다시 보이게 하기
- 관리 이력: 누가, 언제, 왜 처리했는지 확인하기

관리자가 수정해도 원래 작성자는 바뀌지 않습니다.
다른 회원의 비밀번호를 보는 기능은 없습니다.

이 안내서는 명령어를 알려주는 자료입니다.
읽는 것만으로 설정이나 DB가 변경되지는 않습니다.

==================================================
2. 네 명이 같이 개발한다면?
==================================================

각자 컴퓨터에 별도 DB를 사용한다면,
각자 자신의 DB에서 관리자 계정을 지정하면 됩니다.

DB는 회원 정보와 글을 저장하는 보관함이라고 생각하세요.
네 명의 보관함이 서로 다르므로 회원 번호도 다를 수 있습니다.

예시:
- 민수 PC: 민수 계정의 회원 번호가 2
- 지수 PC: 지수 계정의 회원 번호가 5

민수는 ADMIN_USER_ID=2로 설정하고,
지수는 ADMIN_USER_ID=5로 설정합니다.
위 숫자를 그대로 따라 쓰지 말고 자신의 번호를 확인하세요.

각자의 관리자 설정은 다른 팀원에게 영향을 주지 않습니다.
단, 모두 같은 서버와 DB를 사용한다면 그 환경은 관리자 1명입니다.
이 경우 담당자 한 명을 정하고 설정을 함께 관리하세요.

GitHub로 공유할 것:
- 관리자 기능이 들어 있는 파이썬 코드
- 관리자 HTML과 CSS
- 테스트 코드와 이 안내서
- DB 준비 명령이 들어 있는 admin_commands.py

각자 보관할 것:
- 실제 DB 파일
- .env 파일
- 비밀번호, SECRET_KEY, API 키
- 프로젝트 방침에 따라 공유하지 않는 migrations 폴더

DB 파일을 공유하지 않아도 같은 테이블을 준비하는 코드는 필요합니다.
이번 기능은 admin-init-db 명령으로 관리자용 테이블을 만듭니다.

==================================================
3. 시작 전 준비
==================================================

다음 조건이 준비된 PC를 기준으로 설명합니다.

[ ] 관리자 기능 코드가 프로젝트에 들어 있다.
[ ] .venv 폴더가 있고 필요한 패키지가 설치되어 있다.
[ ] 기존 회원·여행지 등 앱용 DB가 준비되어 있다.
[ ] 관리자에게 사용할 기존 회원 계정이 있다.

처음 프로젝트를 받은 PC에서 .venv나 DB 자체가 없다면
먼저 팀의 기본 설치 과정을 진행해야 합니다.
admin-init-db는 사이트 전체 DB를 처음 만드는 명령이 아닙니다.

새 관리 테이블이 없어서 사이트가 오류를 내는 경우에는
아래 5번을 먼저 완료한 뒤 회원가입을 진행하면 됩니다.

==================================================
4. 터미널 열기
==================================================

VS Code 또는 PyCharm에서 프로젝트 폴더를 열고 터미널을 여세요.
config.py와 requirements.txt가 보이는 폴더에서 실행해야 합니다.

아래 설명은 Windows의 Git Bash 기준입니다.
명령은 한 줄씩 입력하고 Enter를 누르세요.
$ 또는 >>> 기호는 직접 입력하지 않습니다.

현재 예시 프로젝트 폴더로 이동:

cd /d/PGH/flask_web_project-main

가상환경 켜기:

source .venv/Scripts/activate

팀원의 폴더 위치가 다르면 cd 뒤의 경로를 바꿔야 합니다.
이미 올바른 폴더와 가상환경을 사용 중이면 다시 할 필요는 없습니다.

PowerShell을 사용한다면 이동과 활성화 명령은 다음과 같습니다.

cd D:\PGH\flask_web_project-main
.\.venv\Scripts\Activate.ps1

PowerShell에서 실행 정책 오류가 나면 Git Bash를 사용하거나,
활성화 없이 아래처럼 파이썬 경로를 직접 사용할 수 있습니다.

.\.venv\Scripts\python.exe -m flask --app odysay admin-check

이후 안내의 python 부분을 위 실행 파일 경로로 바꾸면 됩니다.

==================================================
5. 관리자용 저장 공간 준비
==================================================

서버가 실행 중이면 해당 터미널에서 Ctrl + C로 멈추세요.
그다음 다음 명령을 실행합니다.

python -m flask --app odysay admin-init-db

이 명령이 하는 일:
1) 현재 SQLite DB를 백업합니다.
2) 게시 중단 상태를 저장하는 테이블을 만듭니다.
3) 관리자 처리 이력을 저장하는 테이블을 만듭니다.

정상이라면 '관리 테이블 준비 완료'와 백업 경로가 나옵니다.
백업은 instance/admin-backups 폴더에 저장됩니다.
이미 테이블이 있으면 다시 만들지 않습니다.

주의:
이 명령은 기존 회원·게시글 테이블의 누락이나 모든 DB 오류를
자동으로 고치는 명령은 아닙니다. 오류가 나오면 다음 단계로
넘어가지 말고 메시지를 확인하세요. DB를 지우지 마세요.

==================================================
6. 관리자에게 사용할 회원 번호 찾기
==================================================

로그인 아이디와 회원 번호는 다릅니다.

예시:
- 로그인 아이디(username): minsu
- 회원 번호(id): 3

설정에는 로그인 아이디가 아니라 숫자 회원 번호를 넣습니다.

먼저 실행:

python -m flask --app odysay shell

>>> 표시가 나오면 다음을 한 줄씩 입력하세요.
minsu 부분만 본인의 실제 로그인 아이디로 바꿉니다.

from odysay.models import User
user = User.query.filter_by(username="minsu").first()
print(user.id if user else "해당 회원이 없습니다")

숫자가 나오면 기록해 두세요.
'해당 회원이 없습니다'라면 아이디가 정확한지 확인하세요.
회원가입이 안 되어 있다면 먼저 가입해야 합니다.

확인이 끝나면 종료:

exit()

이 과정에서 비밀번호를 입력하거나 공유할 필요는 없습니다.

==================================================
7. .env 파일에 관리자 번호 넣기
==================================================

프로젝트 최상위 폴더의 .env 파일을 편집기로 여세요.
파일 이름은 .env입니다. .env.txt로 만들면 안 됩니다.

회원 번호가 3이었다면 다음 한 줄을 추가합니다.

ADMIN_USER_ID=3

이미 ADMIN_USER_ID 줄이 있다면 기존 줄만 수정하세요.
같은 설정을 여러 줄로 추가하지 마세요.

기존 SECRET_KEY와 API 키는 지우거나 팀원에게 보내지 마세요.
현재 코드에서는 SECRET_KEY가 dev이면 관리자 접근을 막습니다.

안전한 SECRET_KEY가 아직 없다면 팀 담당자와 확인한 뒤
터미널에서 다음 명령으로 임의의 키를 만들 수 있습니다.

python -c "import secrets; print(secrets.token_hex(32))"

출력된 값을 자신의 .env의 SECRET_KEY 값으로 넣습니다.
이미 안전한 키가 있으면 새로 만들 필요가 없습니다.
키를 변경하면 기존 로그인은 다시 해야 할 수 있습니다.
출력된 키를 채팅이나 GitHub에 올리지 마세요.

설정 예시는 다음과 같습니다. 자리표시자를 그대로 입력하지 마세요.

SECRET_KEY=본인의_안전한_키
ADMIN_USER_ID=본인이_확인한_숫자

.env를 저장한 뒤 다음 단계로 진행합니다.

==================================================
8. 관리자 설정 확인과 서버 실행
==================================================

먼저 설정 확인:

python -m flask --app odysay admin-check

정상 출력 예시:

관리자 확인: minsu (ID 3)

다음으로 서버 실행:

python -m flask --app odysay run --debug

이 명령은 로컬 개발용입니다.
.env를 바꿨다면 기존 서버를 종료하고 다시 실행하세요.

브라우저 주소창에 입력:

http://127.0.0.1:5000/homepage/main

설정한 관리자 계정으로 로그인합니다.
그다음 다음 주소에 접속하세요.

http://127.0.0.1:5000/admin/

마이페이지의 '콘텐츠 관리' 버튼으로 들어가도 됩니다.

중요:
HTML 파일을 더블클릭해서 열면 안 됩니다.
file:///D:/... 같은 주소는 Flask 서버를 거치지 않습니다.
반드시 http://127.0.0.1:5000/... 주소를 사용하세요.

==================================================
9. 내용 수정하기
==================================================

1) 관리자 화면에 들어갑니다.
2) 여행지, 게시글, 리뷰 등 원하는 종류를 선택합니다.
3) 검색하거나 목록에서 대상을 찾습니다.
4) '내용 및 관리'를 누릅니다.
5) '내용 수정' 영역에서 수정합니다.
6) '수정 사유'를 입력합니다.
7) '수정 내용 저장'을 누릅니다.
8) 관리 이력에서 변경 전후 내용을 확인합니다.

수정 사유 예시:
- 여행지 이름 오타 수정
- 잘못된 소개 내용 정정

다른 회원의 콘텐츠 수정은 관리자 화면에서 진행하세요.
일반 작성자용 수정 버튼은 기존 작성자 권한을 사용합니다.

관리자가 수정해도 원래 작성자의 회원 번호는 유지됩니다.
여행지는 연결된 등록 정보와 상세 정보를 함께 수정합니다.

사진은 기존 파일명 목록에서 제외하거나 순서를 바꿀 수 있습니다.
이 관리자 편집기는 새 사진을 업로드하는 기능은 제공하지 않습니다.

==================================================
10. 게시 중단하기
==================================================

1) 대상의 '내용 및 관리' 화면에 들어갑니다.
2) '게시 상태' 영역을 찾습니다.
3) '처리 사유'에 중단 이유를 적습니다.
4) '게시 중단'을 누릅니다.

처리 사유 예시:
- 잘못된 정보가 있어 확인하는 동안 중단
- 개인정보가 포함되어 수정 전까지 중단

중단하면:
- 일반 목록과 관련 API에서 보이지 않습니다.
- 직접 상세 주소를 입력해도 일반 화면에서 볼 수 없습니다.
- 글 자체를 삭제하지 않으므로 복원할 수 있습니다.
- 관리자도 일반 화면에서는 볼 수 없고 관리자 화면에서 확인합니다.

여행지를 중단하면 연결된 리뷰·여행톡·댓글도 일반 화면에서
접근하지 못합니다. 연결 데이터는 삭제하지 않습니다.

사진 원본 파일은 삭제하지 않습니다.
이미 알고 있는 사진 파일의 직접 URL까지 막는 기능은 아닙니다.

==================================================
11. 복원하기
==================================================

1) 관리자 목록에서 상태를 '게시 중단'으로 선택합니다.
2) 검색 버튼을 누릅니다.
3) 대상의 '내용 및 관리'를 누릅니다.
4) 복원 이유를 입력합니다.
5) '게시 복원'을 누릅니다.

예시:
여행지를 중단하면 연결된 댓글도 가려집니다.
여행지를 복원하면 원래 공개 상태였던 댓글은 다시 보입니다.
하지만 따로 중단했던 댓글은 그 댓글도 별도로 복원해야 합니다.

댓글만 복원했는데 여전히 안 보인다면,
댓글이 속한 게시글이나 여행지도 중단되어 있는지 확인하세요.

중단된 글의 내용을 수정하는 것만으로 자동 복원되지는 않습니다.

==================================================
12. 관리 이력 확인하기
==================================================

관리자 화면 위쪽에서 '관리 이력'을 누르세요.

확인할 수 있는 항목:
- 어떤 콘텐츠를 처리했는지
- 수정, 게시 중단, 복원 중 어떤 작업인지
- 처리한 관리자 회원 번호
- 처리 사유
- 처리 시간
- 변경 전후 내용

시간은 UTC 기준으로 표시됩니다.
한국 시간은 UTC보다 9시간 빠릅니다.
예: UTC 01:00은 한국 시간 10:00입니다.

같은 상태로 다시 중단하거나 복원하면 중복 이력을 만들지 않습니다.
일반 회원의 모든 수정 내역까지 기록하는 기능은 아닙니다.

==================================================
13. 팀원 네 명이 확인할 테스트
==================================================

각자 자신의 PC에서 아래 사항을 확인하세요.
가능하면 테스트용 글을 만들어 진행하세요.

[ ] 관리자 계정에서 콘텐츠 관리 화면이 열린다.
[ ] 일반 회원에게 콘텐츠 관리 버튼이 보이지 않는다.
[ ] 일반 회원이 /admin/ 주소를 직접 입력하면 차단된다.
[ ] 관리자가 다른 회원의 글을 수정할 수 있다.
[ ] 수정해도 원래 작성자는 유지된다.
[ ] 중단한 콘텐츠가 일반 목록에서 사라진다.
[ ] 중단한 콘텐츠의 상세 주소도 접근되지 않는다.
[ ] 복원하면 다시 보인다.
[ ] 처리 사유와 변경 전후 기록이 남는다.

자동 테스트를 실행하려면:

python -m unittest discover -s tests -p test_admin_moderation.py -v

현재 테스트는 메모리 안에 별도 DB를 만들어 검사합니다.
실제 회원이나 게시글을 수정하지 않습니다.
마지막에 OK가 나오면 작성된 검사 항목을 통과한 것입니다.
FAIL 또는 ERROR가 나오면 해당 내용을 확인하세요.
OK가 모든 브라우저 동작까지 보장하는 것은 아닙니다.

==================================================
14. 자주 나오는 오류
==================================================

[403 Forbidden]
접근 권한이 없다는 뜻입니다.
- 관리자 계정으로 로그인했나요?
- .env에는 올바른 숫자 회원 ID를 넣었나요?
- 설정 후 서버를 다시 실행했나요?
- admin-check가 통과하나요?

[관리자가 아직 지정되지 않았습니다]
.env에 ADMIN_USER_ID가 있는지 확인하세요.

[ADMIN_USER_ID는 회원 ID 숫자 하나여야 합니다]
로그인 아이디나 이름을 넣으면 안 됩니다.
6번에서 확인한 숫자만 넣으세요.

[활성 상태의 기존 회원을 지정하세요]
해당 번호의 회원이 없거나 탈퇴한 계정일 수 있습니다.

[SECRET_KEY를 안전한 값으로 설정하세요]
7번의 키 설정 설명을 확인하세요.

[No such command 'admin-init-db']
관리자 코드가 빠졌거나 다른 프로젝트를 실행했을 수 있습니다.
odysay/admin_commands.py가 있는지, __init__.py에서
register_commands(app)를 호출하는지 확인하세요.

[no such table: content_moderation 또는 moderation_log]
5번 admin-init-db를 실행했는지 확인하세요.

[no such table: user 또는 trip_locationmd]
기본 앱용 DB 준비가 되지 않은 것입니다.
admin-init-db만으로 해결되지 않으므로 팀 담당자에게 확인하세요.

[CSRF 관련 400 오류]
오래 열어 둔 페이지라면 새로고침 후 다시 시도하세요.
필요하면 로그아웃 후 다시 로그인하세요.
해결하려고 코드에 @csrf.exempt를 임의로 추가하지 마세요.

[409와 함께 중단된 하위 콘텐츠 메시지]
작성자가 글을 삭제하면서 관리자가 중단한 댓글 등이 함께
사라지는 것을 막은 것입니다. 관리자에게 상태 확인을 요청하세요.

==================================================
15. 가장 짧은 작업 순서
==================================================

각 팀원 PC에서:

1) 관리자 기능 코드를 받는다.
2) 프로젝트 폴더에서 가상환경을 켠다.
3) admin-init-db로 관리 테이블을 준비한다.
4) 관리자에게 사용할 기존 회원 번호를 확인한다.
5) .env에 ADMIN_USER_ID를 지정한다.
6) admin-check로 설정을 확인한다.
7) 서버를 재시작한다.
8) 지정 회원으로 로그인한다.
9) /admin/에서 수정·중단·복원을 확인한다.
10) 자동 테스트와 일반 회원 권한 테스트를 한다.

실제 서비스 서버의 관리자 지정은 운영 담당자와 따로 결정합니다.
로컬 개발용 설정을 운영 설정에 그대로 복사하지 마세요.
