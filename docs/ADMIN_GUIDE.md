# 관리자 콘텐츠 관리

## 사용 범위

관리자 한 명이 여행지, 커뮤니티 게시글, 리뷰, 커뮤니티 댓글, 여행톡, 여행톡 댓글을
`/admin/`에서 조회·수정·게시 중단·복원할 수 있습니다. 작성자 ID는 바뀌지 않습니다.
일반 작성자용 수정/삭제 화면은 기존 본인 권한을 유지하고, 다른 사람의 콘텐츠 관리는
감사 이력이 남는 관리자 화면을 통해 수행합니다.

사진은 기존 파일의 제외·순서 변경을 지원합니다. 새 사진 업로드는 관리자 편집기에 포함하지 않습니다.
회원 비밀번호 변경, 계정 정지, 찜/좋아요 수 조작은 콘텐츠 관리 대상이 아닙니다.

## 최초 준비

1. 서버를 중지합니다.
2. 가상환경에서 다음 명령을 실행합니다.

```bash
python -m flask --app odysay admin-init-db
```

기존 SQLite DB를 `instance/admin-backups/`에 백업한 후, `content_moderation`과
`moderation_log`, `content_reports` 관리·신고 테이블을 추가합니다. 여러 번 실행해도 기존 데이터는 유지됩니다.
사용자의 기존 방침에 따라 migrations 폴더를 Git에 올리지 않으며, 다른 PC에서도
이 명령을 실행해야 새 관리 테이블이 만들어집니다. 기존 앱 테이블이 이미 준비된 DB가 필요합니다.
이 명령은 기존 migration 이력을 초기화하거나 stamp하지 않습니다.

3. 관리자에게 사용할 기존 회원 ID 하나를 서버의 `.env`에 지정합니다.

```dotenv
ADMIN_USER_ID=실제_회원_ID_숫자
```

위 문자열은 예시 자리표시자입니다. 아이디(username)가 아닌 숫자 PK를 지정합니다.
기존 SECRET_KEY와 API 키는 지우지 마세요. config.py는 이제 .env의 SECRET_KEY를 사용합니다.
개발용 기본 키 `dev`로는 관리자 접근이 허용되지 않습니다. 키 변경 시 기존 세션은 다시 로그인해야 합니다.

4. 아래로 설정을 확인하고 서버를 다시 실행합니다.

```bash
python -m flask --app odysay admin-check
python -m flask --app odysay run --debug
```

지정 회원으로 로그인한 뒤 마이페이지의 **콘텐츠 관리** 또는 `/admin/`에 접속합니다.
관리자 미지정·다른 회원·비로그인·탈퇴 계정에는 403을 반환합니다.
공개 회원가입 폼에는 권한 부여 기능이 없습니다. 관리자 교체는 서버 설정에서만 수행합니다.

## 게시 중단 규칙

- 목록·검색·지도 API·직접 상세 조회·댓글/리뷰 관련 요청에서 중단 콘텐츠를 제외합니다.
- 작성자와 관리자도 일반 사용자 화면에서는 중단 콘텐츠를 볼 수 없습니다.
- 관리자 화면만 중단된 원본을 조회하고 수정·복원할 수 있습니다.
- 상위 여행지가 중단되면 하위 리뷰·여행톡·댓글도 노출되지 않습니다.
- 부모를 복원해도 별도로 중단한 자식 콘텐츠는 계속 중단됩니다.
- 하위 콘텐츠만 복원했는데 부모가 중단 중이면 여전히 일반 화면에는 표시되지 않습니다.
- 작성자의 영구 삭제로 관리자가 중단한 하위 데이터가 사라지지 않도록 해당 삭제는 409로 막습니다.
- 원본 데이터와 사진 파일은 삭제하지 않습니다. 이미 알려진 `/static/uploads/...` 사진 URL 자체의
  접근 차단이나 외부 캐시 삭제는 이 기능 범위가 아닙니다. 비공개 파일이 필요하면 별도 파일 제공 정책이 필요합니다.

## 수정 및 이력

여행지 수정은 `TripLocationmd`와 연결된 `Uploadmd`의 공통 필드를 함께 갱신합니다.
관리자가 폼에 user_id나 기타 임의 필드를 보내도 편집 허용 목록에 없는 항목은 변경하지 않습니다.
중단 상태에서 내용을 수정해도 자동 복원되지 않습니다.
처리 사유(1~500자)는 필수이며, 수정 전후 스냅샷·처리자·UTC 시각을 같은 DB 트랜잭션에 기록합니다.
중단·복원을 같은 상태로 반복 요청하면 중복 이력을 생성하지 않습니다.
기존 일반 회원의 모든 편집 이력을 수집하는 기능은 아닙니다.

## 개발 구조

- `odysay/moderation.py`: 관리자 판별·접근 제한·공개 ORM 조회 필터·중단 하위 데이터 보호
- `odysay/views/admin_views.py`: 콘텐츠 목록·수정·중단·복원·관리 이력
- `odysay/models.py`: 관리 상태 및 이력 모델
- `odysay/admin_commands.py`: DB 준비·계정 설정 확인
- `odysay/templates/admin/`, `odysay/static/css/admin.css`: 관리자 화면

공개 조회 필터는 HTTP 요청의 SQLAlchemy ORM SELECT에 적용됩니다. raw SQL이나 직접적인 bulk UPDATE/DELETE에는
자동 적용되지 않으므로 새 경로를 추가할 때는 반드시 공개 모델 조회로 대상과 상위를 검증해야 합니다.
관리자 예외 플래그는 권한을 검사한 데코레이터에서 요청 단위로만 설정됩니다.
이 관리 상태는 유형+ID를 가리키므로 데이터 복원·직접 SQL import 시 기존 ID를 다른 콘텐츠에 재사용하지 마세요.

커뮤니티 변경 API의 CSRF 예외를 제거했으며, community_detail 템플릿은 POST 요청에 토큰을 보냅니다.
인증은 검증된 g.user만 사용하며 오래된 세션 키를 우회 인증으로 사용하지 않습니다.

## 테스트

```bash
python -m unittest discover -s tests -p test_admin_moderation.py -v
```

테스트는 메모리 DB를 사용합니다. 권한·CSRF·6종 콘텐츠 중단/복원·하위 노출 제한·데이터 보존·
필드 검증·여행지 동기화·작성자 보존·이력·일반 삭제를 통한 복원 데이터 유실 방지를 검사합니다.
일부 시나리오는 비즈니스 권한을 단독 검증하기 위해 테스트 설정에서만 CSRF를 끄고,
별도 테스트에서는 실제 CSRF 거절과 유효 토큰 사용을 검사합니다.
