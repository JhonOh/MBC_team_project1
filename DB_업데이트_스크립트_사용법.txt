DB 업데이트 스크립트 사용법 (2026-10-07)

이번 방식은 마이그레이션 파일을 공유하지 않는 기존 SQLite DB용입니다.
이 방식 사용 시 이전 가이드의 db upgrade, db stamp, repair_udated_at.py,
admin-init-db를 순서대로 실행하지 마세요. 관리자 계정 설정은 별도입니다.

1. 서버와 Flask shell을 종료합니다.
2. 최신 프로젝트 코드(update_database.py, config.py, odysay/models.py 포함)를 받습니다.
   스크립트 하나만 받는 것이 아닙니다. 기존 프로젝트의 .venv와 의존성이 필요합니다.
3. 프로젝트 최상위 폴더에서 실행합니다.

.\.venv\Scripts\python.exe .\update_database.py --check

4. '적용 가능'일 때만 아래 명령을 실행합니다.

.\.venv\Scripts\python.exe .\update_database.py --apply

5. 성공 후 --check를 다시 실행하고 서버를 시작합니다.
   '이미 적용되어 있습니다. 변경 없음'이면 추가 적용은 필요 없습니다.

백업은 대상 DB와 같은 폴더에 *_backup_update_날짜시간.db 이름으로 생성됩니다.
변경이 없거나 점검에서 충돌하면 백업과 변경을 수행하지 않습니다.
적용은 하나의 트랜잭션이며 중간 오류는 롤백합니다.
읽기 전용 check는 DB를 수정하지 않습니다.
기존 가입일과 태그 값은 임의로 채우지 않습니다.
단, is_active 컬럼이 없던 기존 계정에는 활성값 1을 부여합니다.

지원 범위:
- 기존 회원/게시글/여행지 DB에 지정된 프로필, 좌표, 수정일, 가입일, 태그,
  여행톡 댓글 parent_id 컬럼 추가
- 누락된 찜, 좋아요, 문의, 관리자 기록, 리뷰/여행톡 추천 테이블 생성
- 주요 컬럼 형식, NULL 조건, 기본키, 모델 고유 제약과 외래키 점검
- 모델에 선언된 인덱스가 없으면 생성

지원하지 않는 범위:
- 빈 DB 초기화, 테이블/컬럼 이름 변경, 데이터 삭제나 테이블 재구성
- 모든 과거 버전 자동 복구, 사용자 정의 트리거/추가 제약 전체 검증
- Alembic 버전 동기화, 서버가 종료되었는지 자동 판별

[중단] 메시지가 나오면 자동 변경하지 않습니다.
모델이 예상하는 구조와 다른 DB이므로 출력 내용을 공유하고 별도로 검토하세요.
오류를 숨기기 위해 stamp하거나 DB를 삭제하지 마세요.
백업 파일에는 개인정보가 있을 수 있으므로 GitHub에 올리지 마세요.
.gitignore는 변경할 필요 없습니다. 마이그레이션 파일도 필요하지 않습니다.

기본 대상은 config.py의 절대 SQLite DB 경로입니다.
복사본 검사 시에만 명시적으로 경로를 지정할 수 있습니다.

.\.venv\Scripts\python.exe .\update_database.py --check --database "D:\검증폴더\복사본.db"

이 프로그램은 현재 모델을 참조하지만 추가 가능한 컬럼과 테이블은 제한되어 있습니다.
향후 모델 변경 때는 스크립트와 테스트도 함께 검토해야 합니다.
모든 팀원의 실제 DB에 대한 성공을 보증하지 않습니다.
