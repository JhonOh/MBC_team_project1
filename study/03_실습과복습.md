## 실습 2 — 격리된 ORM 실습 (20분)

프로젝트 최상위 폴더에서 Git Bash 기준으로 실행합니다.

```bash
.venv/Scripts/python.exe study/practice_memory_db.py
```

PowerShell에서는 다음과 같습니다.

```powershell
.\.venv\Scripts\python.exe study/practice_memory_db.py
```

마지막 줄이 `PASS`이면 성공입니다. 실습은 메모리 DB에 회원 2명과 여행지 2개를 만들고, 내 여행지는 1개만 보이는지 검사합니다. 실제 DB·사진·원격 저장소는 변경하지 않습니다. 별도 Flask 서버를 켤 필요도 없습니다.

실행 전에 예상해보세요: flush 후 ID는 있는가? rollback 후 intro는 무엇인가? 비로그인 요청의 상태 코드는 무엇인가?

실습 파일에서 `filter_by`를 제거하면 무엇이 실패할지 예측해보세요. 앱 원본 대신 실습 파일 사본에서 바꿔봅니다. 로그인 세션을 직접 넣는 부분은 화면 테스트를 위한 것이며 실제 비밀번호 로그인 테스트는 아닙니다.

<details><summary>정답과 해설</summary>

flush 후에는 생성된 ID를 사용할 수 있습니다. rollback 후 소개는 커밋했던 `A learning example`입니다. 비로그인은 302, 세션을 설정한 요청은 200입니다. 필터를 제거하면 두 여행지를 가져오므로 `len(mine) == 1` 검사가 실패합니다. 회원 정보가 메모리에 있으므로 서버를 다시 실행해 실제 로그인 화면에서 이 계정으로 로그인할 수는 없습니다.

</details>

## 실습 3 — CSS 적용 원리 관찰 (15분)

로그인 후 내 여행지 페이지에서 개발자 도구 Elements를 엽니다. `.destination-grid`를 선택하고 Computed에서 `grid-template-columns`를 확인합니다. 화면 너비를 1200px → 900px → 480px로 바꿔봅니다. 카드가 없는 경우에도 그리드가 렌더링되지 않는다는 조건을 먼저 확인하세요.

카드가 있다면 개발자 도구에서만 `.destination-card` class를 잠시 제거해보세요. 파일을 저장하지 않아도 테두리와 hover가 바뀌는지 볼 수 있습니다. 새로고침하면 실험이 초기화됩니다.

<details><summary>예상 결과</summary>

공통 CSS 기준으로 3열 → 2열 → 1열입니다. `.destination-card` 규칙은 해당 class를 가진 요소에만 적용됩니다. 자식의 `.card-image` 같은 class는 그대로라 이미지 스타일 일부는 남을 수 있습니다. CSS 파일 하나가 페이지 전체의 모든 모양을 일괄 결정하는 것은 아닙니다.

</details>

## 실습 4 — API 추적 (15분)

`/homepage/trip_list`를 열고 Network에서 Fetch/XHR를 선택한 뒤 새로고침합니다. `/first/places` 요청을 찾아 Response의 필드를 확인합니다. 코드 지도의 endpoint 표에서 담당 함수도 찾아보세요.

`/trip-list/places` 응답과 비교할 때 결과가 같아도 두 쿼리가 같은 것은 아닙니다. 현재 DB에 좌표 없는 여행지가 없다면 필터 차이가 겉으로 드러나지 않을 수 있습니다. 검증을 위해 실제 DB에 데이터를 무작정 추가하지 마세요.

<details><summary>정답과 해설</summary>

`trip_list.js` → `/first/places` → `a0_mapmain_views.places` → 좌표가 NULL이 아닌 `TripLocationmd` 조회입니다. `/trip-list/places`는 `a2_trip_list_views.places`가 담당하며 좌표 유무와 무관하게 조회합니다. 응답 데이터와 UI가 다르면 JSON 필드와 JS 카드 생성 코드도 비교해야 합니다.

</details>

## 스스로 답하는 12문제

1. `url_for('mypage.my_places')`와 `render_template('mypage_my_places.html')`는 각각 무엇을 반환하는가?
2. 파일에 Blueprint가 선언되어 있는데 404가 나는 이유 중 하나는?
3. `g.user`와 `session['user_id']`의 차이는?
4. `TripLocationmd.place_id`와 상세 라우트의 `place_id`는 같은 ID인가?
5. 사진 저장 후 DB commit 실패 시 rollback만 하면 사진도 사라지는가?
6. 외래키와 relationship은 각각 어느 층의 연결인가?
7. 코드에서 모델 이름을 바꾸면 실제 DB 테이블도 자동 변경되는가?
8. 커뮤니티 좋아요와 여행지 찜은 같은 테이블을 쓰는가?
9. 두 CSS 파일 중 뒤에 로드한 파일이 언제나 우선하는가?
10. 충돌 표시를 지웠는데 Git에서 UU가 남는 이유는?
11. git push에 성공하면 PR도 자동으로 병합되는가?
12. .gitignore에 DB 파일명을 넣으면 이미 커밋한 DB도 이력에서 사라지는가?

<details><summary>정답 확인</summary>

1. URL 문자열 / 렌더링된 HTML입니다.
2. 앱 팩토리에서 등록되지 않았거나 요청 URL이 접두사와 다를 수 있습니다.
3. 이번 요청의 회원 객체 / 요청 사이에 유지되는 회원 ID입니다.
4. 아닙니다. 전자는 Uploadmd ID, 현재 상세 URL은 TripLocationmd ID를 조회합니다.
5. 아닙니다. DB 트랜잭션과 파일시스템 작업은 별개입니다.
6. DB 참조 규칙 / 파이썬 객체 탐색 관계입니다.
7. 아닙니다. DB 스키마 변경과 데이터 이관이 별도로 필요합니다.
8. 아닙니다. PostLike와 Bookmark가 분리되어 있습니다.
9. 아닙니다. 선택자 구체성 등 캐스케이드 규칙을 함께 봅니다.
10. index에 해결 완료가 아직 등록되지 않았을 수 있습니다. 파일 확인 후 git add가 필요합니다.
11. 아닙니다. push는 원격 브랜치 업데이트이며 PR 검토·병합은 별도입니다.
12. 아닙니다. ignore는 이미 추적된 파일이나 과거 이력을 지우지 않습니다.

</details>

## 오류 상황 훈련

### A. 내 여행지에서 다른 사람의 카드도 보인다

예상 원인과 확인 파일을 적으세요.

<details><summary>해설</summary>

먼저 `a5_mypage_views.my_places`의 user_id 필터와 로그인 사용자 확인을 봅니다. CSS로 가려서 해결할 문제가 아닙니다. 쿼리 결과에 타인 데이터가 포함됐는지 격리 DB로 재현하세요.

</details>

### B. 커뮤니티 상세는 열리지만 댓글 POST가 실패한다

<details><summary>해설</summary>

GET 성공은 POST 경로의 성공을 보장하지 않습니다. 요청 URL·메서드, 로그인, JSON content, 응답 코드와 본문, 댓글 테이블·외래키를 차례로 확인합니다. 400·401·403·500은 서로 다른 원인일 수 있습니다. 전역 CSRF만 보고 단정하지 말고 해당 함수의 exempt 여부도 확인합니다.

</details>

### C. 최신 main으로 이동했는데 DB 오류가 난다

<details><summary>해설</summary>

Git 브랜치 전환은 ignored DB를 새 모델 구조로 변환하지 않습니다. 코드의 모델과 실제 DB schema가 일치하는지 확인합니다. DB를 삭제하거나 stamp로 오류를 숨기기 전에 현재 DB 백업과 migration 이력을 확인해야 합니다.

</details>
